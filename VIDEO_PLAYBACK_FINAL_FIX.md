# 🎬 Финальное исправление воспроизведения видео

## Проблема

Пользователь сообщал, что видео не воспроизводится в модальном окне, несмотря на наличие контролов.

## Диагностика

После анализа кода были выявлены следующие проблемы:

1. **Отсутствие программного управления видео** - видео полагалось только на нативные контролы браузера
2. **Неправильная инициализация** - видео не имело ref для программного доступа
3. **Отсутствие обработчиков событий** - не было возможности отследить загрузку и ошибки
4. **Блокировка автозапуска** - браузеры блокируют автозапуск видео со звуком

## Решение

### 1. Добавлен useRef для видео элемента

```tsx
const videoRef = useRef<HTMLVideoElement>(null);
```

Это позволяет программно управлять видео элементом.

### 2. Автоматический запуск при открытии модального окна

```tsx
useEffect(() => {
  if (mediaViewer?.visible && mediaViewer.attachment.type === 'video' && videoRef.current) {
    const playVideo = async () => {
      try {
        await videoRef.current?.play();
      } catch (error) {
        console.log('Автозапуск заблокирован, пользователь должен нажать Play');
      }
    };
    setTimeout(playVideo, 100);
  }
}, [mediaViewer]);
```

**Как это работает:**
- При открытии модального окна с видео, ждём 100мс для загрузки
- Пытаемся запустить видео программно
- Если браузер блокирует автозапуск (со звуком), ловим ошибку
- Пользователь может нажать Play вручную

### 3. Улучшенный элемент video

```tsx
<video 
  ref={videoRef}
  src={mediaViewer.attachment.url}
  className="max-w-full max-h-[85vh] rounded-lg"
  controls
  playsInline
  preload="auto"
  onLoadedData={() => console.log('Видео загружено')}
  onError={(e) => console.error('Ошибка загрузки видео:', e)}
  style={{ backgroundColor: '#000' }}
>
  <source src={mediaViewer.attachment.url} type="video/mp4" />
  <source src={mediaViewer.attachment.url} type="video/webm" />
  Ваш браузер не поддерживает воспроизведение видео.
</video>
```

**Ключевые изменения:**
- ✅ `ref={videoRef}` - для программного управления
- ✅ `preload="auto"` - полная загрузка видео (вместо metadata)
- ✅ `onLoadedData` - обработчик успешной загрузки
- ✅ `onError` - обработчик ошибок
- ✅ `style={{ backgroundColor: '#000' }}` - явный чёрный фон
- ✅ Множественные `<source>` для разных форматов
- ✅ Fallback сообщение для неподдерживаемых браузеров

### 4. Остановка видео при закрытии

```tsx
const closeMediaViewer = () => {
  if (videoRef.current) {
    videoRef.current.pause();
  }
  setMediaViewer(null);
};
```

Это предотвращает продолжение воспроизведения после закрытия модального окна.

## Технические детали

### Почему preload="auto" вместо "metadata"?

**`preload="metadata"`:**
- Загружает только информацию о видео (длительность, размеры)
- Быстрее открытие модального окна
- Но видео может не воспроизводиться сразу

**`preload="auto"`:**
- Загружает весь видео файл
- Медленнее открытие, но гарантированное воспроизведение
- ✅ Лучше для модального окна

### Почему множественные source?

```tsx
<source src={url} type="video/mp4" />
<source src={url} type="video/webm" />
```

Браузеры поддерживают разные форматы:
- **MP4 (H.264)** - Chrome, Firefox, Safari, Edge
- **WebM (VP8/VP9)** - Chrome, Firefox, Edge
- **MOV** - Safari

Браузер выберет первый поддерживаемый формат.

### Обработка ошибок автозапуска

```tsx
try {
  await videoRef.current?.play();
} catch (error) {
  console.log('Автозапуск заблокирован, пользователь должен нажать Play');
}
```

**Почему это важно:**
- Современные браузеры блокируют автозапуск видео со звуком
- Политика: https://developer.chrome.com/blog/autoplay/
- Если видео имеет звук, автозапуск блокируется
- Пользователь должен нажать Play вручную
- Мы ловим ошибку и логируем её

## Как это работает теперь

### Сценарий 1: Видео без звука

1. Пользователь кликает на превью видео
2. Открывается модальное окно
3. Видео загружается (`preload="auto"`)
4. Через 100мс вызывается `play()`
5. ✅ Видео автоматически начинает воспроизводиться
6. Пользователь видит контролы

### Сценарий 2: Видео со звуком

1. Пользователь кликает на превью видео
2. Открывается модальное окно
3. Видео загружается
4. Через 100мс вызывается `play()`
5. ❌ Браузер блокирует автозапуск (из-за звука)
6. Ловим ошибку, логируем
7. Пользователь нажимает Play вручную
8. ✅ Видео начинает воспроизводиться

### Сценарий 3: Ошибка загрузки

1. Пользователь кликает на превью
2. Открывается модальное окно
3. Видео не может загрузиться (повреждён файл)
4. Срабатывает `onError`
5. В консоли появляется ошибка
6. Пользователь видит сообщение "Ваш браузер не поддерживает воспроизведение видео"

Если видео не воспроизводится, конвертируйте в MP4:

```bash

ffmpeg -i input.mov -c:v libx264 -c:a aac output.mp4
```

## Дополнительные улучшения (опционально)

### 1. Индикатор загрузки

```tsx
const [isLoading, setIsLoading] = useState(true);

<video 
  onLoadedData={() => setIsLoading(false)}
  // ...
/>
{isLoading && (
  <div className="absolute inset-0 flex items-center justify-center">
    <div className="animate-spin rounded-full h-12 w-12 border-b-2 border-white"></div>
  </div>
)}
```

### 2. Прогресс загрузки

```tsx
const [progress, setProgress] = useState(0);

<video 
  onProgress={(e) => {
    const video = e.currentTarget;
    const buffered = video.buffered;
    if (buffered.length > 0) {
      const progress = (buffered.end(0) / video.duration) * 100;
      setProgress(progress);
    }
  }}
  // ...
/>
```

### 3. Полноэкранный режим

```tsx
const toggleFullscreen = () => {
  if (videoRef.current) {
    if (document.fullscreenElement) {
      document.exitFullscreen();
    } else {
      videoRef.current.requestFullscreen();
    }
  }
};
```
